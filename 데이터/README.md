# 데이터 보관 구조

`원본/`에는 RACOI 공개 화면과 다운로드 API에서 받은 응답을 수정하지 않고 보존합니다. 실제 원본 파일, 수집 이력과 댓글 원문은 Git 추적 대상에서 제외합니다. 현재 확보 범위·구조·누락은 [`노트북/01_RACOI_자료_수집.ipynb`](../노트북/01_RACOI_자료_수집.ipynb)의 실제 실행 표를 기준으로 확인합니다.

| 경로 | 기간 단위·내용 | Git 정책 |
|---|---|---|
| `원본/인터넷반응_주간/` | 주간 RACOI 인터넷반응 XLSX | 실제 파일 제외 |
| `원본/종합반응_월간/` | 월간 RACOI 종합반응 XLSX | 실제 파일 제외 |
| `원본/댓글반응_상세/` | 프로그램·주차별 공개 키워드·감성·연관어 JSON | 실제 파일과 원문 댓글 제외 |
| `원본/수집_메타데이터.jsonl` | 다운로드 시도별 URL·수집 시각·기간·형식·체크섬·파일 경로·상태 이력 | 실제 이력 제외 |

수집 상태에서 `success`는 새 원본 저장, `duplicate`는 기존과 동일한 원본을 재사용한 정상 재실행, `failed`는 실패 사유가 기록된 시도다. `duplicate`는 새 수집 성공 건수에 합치지 않는다. 메타데이터가 가리키는 파일이 실제로 없으면 수집 노트북에서 `누락 파일`로 표시한다.

파일명에는 원천·자료유형·댓글반응의 경우 `pjseq`·주차·체크섬 일부를 포함한다. 원본 SHA-256은 저장 파일의 동일성 확인에 사용하며, 서버 생성 시각이나 JSON 배열 순서처럼 내용과 무관한 차이는 중복 통제를 위한 별도 내용 지문으로만 비교한다.

이슈 #5에서는 원본 XLSX의 실제 데이터 행과 댓글 JSON의 반복 레코드를 MariaDB raw 테이블에 적재한다. 이 과정에서도 원본 Excel·JSON은 수정하지 않으며, 원본 파일 경로·체크섬·시트 또는 배열 위치·수집 시각을 출처 정보로 함께 보존한다.
