# BrandCast 검증 체크리스트

구현 주체는 작업 전에 이 문서를 읽고, 검증 주체는 이 문서로 PR을 검증한다. 역할 분리와 머지 조건은 `AGENTS.md`의 `검증 플로우` 절에 있다.

각 항목에는 무엇을 실행해 확인하는지를 함께 적는다. 확인 방법이 없는 항목은 통과 여부가 해석에 맡겨지므로 체크리스트에 넣지 않는다.

표기

- `자동`: `.github/workflows/verify.yml`이 검사한다. 통과하지 못하면 머지가 막힌다.
- `검증`: 검증 주체가 직접 실행해 확인한다.
- `반송`: 위반 시 직접 수정하지 않고 구현 주체에게 되돌린다.

## 1. 모든 PR 공통

| 구분 | 항목 | 확인 방법 |
|---|---|---|
| 자동 | 원본 데이터·비밀 설정이 커밋되지 않음 | `git ls-files`에 `데이터/원본` 실제 파일과 `.env`가 없는지 검사 |
| 자동 | 접속 문자열·비밀번호 하드코딩 없음 | 노트북 코드 셀과 출력에서 접속 문자열 패턴 검사 |
| 자동 | 별도 `SQL/` 폴더와 키워드 사전 CSV 없음 | 추적 파일 경로 검사 |
| 검증 | 커밋·PR 제목이 한국어 명사형으로 끝남 | `git log --oneline origin/main..HEAD`와 PR 제목 확인 |
| 검증 | PR 본문이 템플릿 항목을 모두 채우고, 해당 없는 항목에 사유를 적음 | PR 본문과 `.github/pull_request_template.md` 대조 |
| 검증 | 관련 이슈가 `Closes` 또는 `Relates to`로 연결됨 | PR 본문 확인 |
| 검증 | 변경 범위가 이슈 범위를 넘지 않음 | `git diff --stat origin/main..HEAD`와 이슈 작업 범위 대조 |
| 반송 | 실제 수집·실행으로 확인하지 않은 값이 결과처럼 적혀 있지 않음 | 문서·노트북의 수치를 원본 또는 SQL 결과와 대조 |

## 2. 수집 코드 (`수집/`)

| 구분 | 항목 | 확인 방법 |
|---|---|---|
| 검증 | 같은 입력 재실행 시 중복 파일이 생기지 않음 | 같은 조건으로 두 번 실행한 뒤 `데이터/원본` 파일 수와 메타데이터 상태 비교 |
| 검증 | 빈 응답과 오류 페이지가 성공으로 저장되지 않음 | 응답 본문이 빈 배열·빈 객체인 경우의 처리 확인 |
| 검증 | 수집 메타데이터와 실제 원본 파일이 일치함 | 메타데이터의 `file_path` 집합과 디스크 파일 집합을 비교해 고아 파일과 누락 파일 확인 |
| 검증 | 기간 매개변수가 `.env` 설정과 실행 인자 양쪽에서 동작함 | 인자 없이, 인자만, `.env`만 지정한 세 경우 실행 |
| 검증 | 실패가 성공으로 기록되지 않음 | 메타데이터의 `collection_status` 분포와 실패 사유 확인 |
| 자동 | 접근 정보·쿠키·토큰이 코드에 없음 | 비밀 패턴 검사 |

## 3. 적재·품질·전처리 노트북 (`노트북/02`)

| 구분 | 항목 | 확인 방법 |
|---|---|---|
| 검증 | 노트북이 처음부터 끝까지 실행됨 | 커널 재시작 후 전체 실행, 오류 셀 없음 확인 |
| 검증 | MariaDB 버전이 실행 결과로 기록됨 | `SELECT VERSION()` 결과 셀 확인 |
| 검증 | 원본 테이블이 적재 후 수정되지 않음 | 전처리 SQL이 `raw_` 테이블에 `UPDATE`·`DELETE`를 수행하지 않는지 확인 |
| 검증 | 원본과 분석용 테이블의 행 수·합계 비교 결과가 표로 표시됨 | 해당 결과 표 확인 |
| 검증 | 미수집과 실제 0이 구분됨 | 품질검사 SQL의 NULL·0 처리 기준과 결과 표 확인 |
| 검증 | 분석용 테이블의 한 행 단위와 키가 결과로 확인됨 | grain 검증 SQL의 중복 건수 확인 |
| 자동 | 모든 SQL 셀 상단에 목적·입력·출력 단위·분석 기간·NULL 처리 주석이 있음 | SQL 셀 상단 20줄 검사 |

## 4. Q1~Q6 질문 노트북 (`노트북/03`~`08`)

| 구분 | 항목 | 확인 방법 |
|---|---|---|
| 자동 | 첫 셀이 대제목 표지, 둘째 셀이 핵심 질문 카드 | 셀 유형과 내용 검사 |
| 자동 | 계획된 그래프가 정확히 2개 | `savefig` 호출 수 검사 |
| 자동 | 그래프가 질문별 폴더에 저장됨 | `savefig` 경로에 `그래프/Q*` 포함 여부 검사 |
| 자동 | SQL 셀이 존재하고 상단 5항목 주석이 있음 | SQL 셀 검사 |
| 자동 | Python에서 집계·파생·순위를 다시 계산하지 않음 | `groupby`, `merge`, `pct_change`, `rolling`, `polyfit` 등 호출 검사 |
| 검증 | 노트북이 처음부터 끝까지 실행됨 | 커널 재시작 후 전체 실행 |
| 검증 | 그래프 PNG가 실제로 생성되고 노트북 표시본과 데이터·제목·기간이 일치함 | 저장 파일의 수정 시각과 내용을 표시 셀과 대조 |
| 검증 | 표에 단위·기간·표본 수와 전체 행 수가 표시됨 | 결과 표와 설명 셀 확인 |
| 검증 | 후보 표에 이전 단계 순위, 현재 순위, 통과 여부, 제외 사유가 있음 | 후보 선별 결과 표 확인 |
| 검증 | 후보 수가 상한을 넘지 않고, 미달 시 사유가 적혀 있음 | 후보 수와 설명 대조 |
| 검증 | 결론이 핵심 질문에 답하고 다음 질문으로 넘길 후보를 명시함 | 결론 셀 확인 |
| 반송 | 지표 정의와 계산식이 개발 계획서의 명세와 일치함 | 계획서의 Q별 산식과 SQL 대조 |
| 반송 | 그래프 명세가 계획서에 정의된 2개와 일치함 | 계획서의 그래프 명세와 대조 |

## 5. 문서

| 구분 | 항목 | 확인 방법 |
|---|---|---|
| 검증 | 계획 문서의 완료 체크박스가 실제 상태와 일치함 | 체크된 항목마다 근거가 되는 코드·실행 결과 확인 |
| 검증 | 데이터 사전이 실제 적재 결과를 기준으로 작성됨 | 테이블·컬럼 목록을 실제 스키마와 대조 |
| 검증 | 문서 간 상호 링크가 실제 경로를 가리킴 | 링크 대상 파일 존재 확인 |
| 검증 | 수집·분석 한계가 확인된 사실만 담음 | 한계 문서의 각 항목에 대한 근거 확인 |
| 반송 | 광고 효과·ROI를 입증하거나 예측한다는 표현이 없음 | 표현 검토 |

## 6. 검증 결과 기록

- 통과: PR에 `검증-통과` 라벨을 붙인다. 직접 수정한 항목이 있으면 수정 커밋과 함께 PR 코멘트에 무엇을 고쳤는지 적는다.
- 반송: `검증-반송` 라벨을 붙이고 위반 항목, 확인 방법, 재현 결과를 PR 코멘트에 적는다.
- 재검증: 새 커밋이 올라오면 `검증-통과` 라벨이 자동 제거된다. 다시 검증한 뒤 라벨을 붙인다.
