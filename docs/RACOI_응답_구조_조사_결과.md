## 1. 조사 목적

RACOI 공개 화면과 다운로드 기능에서 실제 응답을 소량 받아 다음 사항을 확인했다.

- 인터넷반응과 종합반응 Excel 다운로드 요청 구조
- 최신 완료 주차와 월 코드
- Excel 시트, 헤더, 병합 셀, 실제 데이터 행과 컬럼 구조
- `pjseq=11487` 댓글반응 상세의 공개 JSON 엔드포인트
- 댓글 키워드, 감성, 워드클라우드와 연관어 데이터 제공 범위
- Q4 관심 주제와 Q6 감성 위험 분석의 구현 가능 범위

이번 조사에서 받은 실제 원본은 `데이터/원본` 아래에 보존하며 `.gitignore`에 따라 Git에는 포함하지 않는다.

## 2. 공식 공개 범위

KOBACO의 RACOI 안내에 따르면 인터넷반응은 주간, 종합반응은 월간 자료이며 2017년 5월 이후 조사를 제공한다. 주요 조사 지표는 미디어버즈의 뉴스·동영상 수와 시청자버즈의 게시글·댓글·동영상 조회 수다.

확인한 공식 페이지:

- KOBACO RACOI 안내: <https://kobaco.co.kr/site/main/content/racoi_info>
- 인터넷반응·종합반응 다운로드: <https://www.racoi.or.kr/kobaco/excel/response.do?menu=ibuzz>
- 댓글반응 상세: <https://www.racoi.or.kr/kobaco/nreport/pjinfo.do?pjseq=11487>

## 3. 다운로드 요청 구조

### 3.1 인터넷반응·종합반응

인터넷반응과 종합반응은 같은 다운로드 화면과 POST 엔드포인트를 사용한다.

| 항목 | 확인 결과 |
|---|---|
| 화면 | `GET /kobaco/excel/response.do?menu=ibuzz` 또는 `menu=total` |
| 다운로드 | `POST /kobaco/excel/mexceldown.do` |
| 인터넷반응 구분 | `rtype=1` |
| 종합반응 구분 | `rtype=2` |
| 기간 코드 | 인터넷반응 `YYYYWW`, 종합반응 `YYYYMM` |
| 응답 | XLSX 첨부 파일 |
| MIME | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |

다운로드 폼에서 확인한 주요 필드:

```text
rtype
st
ed
datep_st
datep_ed
filterConditions
parClassList
classList
channelList
siteList
ccSiteList
siteSelectName
category
rcOnlySiteList
```

장르 전체 조건은 `cat001`부터 `cat004`까지의 조건을 JSON 배열로 전달한다. 채널과 세부 사이트를 선택하지 않은 전체 다운로드에서는 관련 목록을 빈 배열로 전달할 수 있었다.

### 3.2 댓글반응 상세

댓글반응 화면은 `application/x-www-form-urlencoded` POST 본문의 `param` 필드에 JSON 객체를 넣어 공개 API를 호출한다.

```text
param={"pjseq":11487,"nweek":"202646"}
```

API 응답 본문은 유효한 JSON이지만 일부 응답에서 `Content-Type` 헤더가 확인되지 않았다. 수집 코드는 헤더만 믿지 않고 JSON 파싱 가능 여부를 함께 검증해야 한다.

### 7.3 감성 데이터 제약

- 감성 추이와 도넛 분포 API는 `positivescore`와 `negativescore` 두 값만 제공한다.
- 두 값은 조사 표본에서 합계가 1인 비율 형태다.
- 중립 워드클라우드 키워드는 제공되지만 중립 감성 비율이나 건수는 제공되지 않는다.
- 현재 Q6 계획의 긍정·중립·부정 100% 누적 막대그래프는 이 API만으로 직접 구현할 수 없다.
- 추가 공식 원천에서 중립 비율을 찾지 못하면 Q6 그래프를 긍정·부정 2분포로 수정하거나 중립을 미제공으로 표시해야 한다.

### 7.4 분석 가능성 판단

| 질문 | 판단 | 근거 |
|---|---|---|
| Q4 관심 주제 | 구현 가능 | 일반·긍정 키워드 빈도, 감성 워드클라우드, 연관어 조합과 네트워크 제공 |

댓글 원문은 응답에 포함되지 않았고 집계 키워드와 점수만 제공됐다. 프로젝트는 공개 집계 결과를 우선 사용하며 댓글 원문을 별도로 수집하거나 자체 감성 모델로 대체하지 않는다.

최신 제공 주차 `202646`과 직전 주차 `202645`를 같은 조건으로 요청하여 응답 구조를 비교했다.

| 긍정댓글 키워드 | `nweek`, `rk1`, `keyword`, `frequency` | 문자열·정수 | 20 | 20 | 예 |
| 감성 추이 | `nweek`, `positivescore`, `negativescore` | 문자열·실수 | 14 | 14 | 예 |
| 감성 분포 | `nweek`, `positivescore`, `negativescore` | 문자열·실수 | 1 | 1 | 예 |
| 감성 워드클라우드 | `sentimenttypecode`, `nweek`, `keyword`, `programid`, `frequency` | 문자열·정수 | 200 | 200 | 예 |

확인 결과:

- 모든 응답은 최상위 JSON 배열이다.
- 두 주차 모든 레코드에서 NULL 값이 발견되지 않았다.
- 필드명과 첫 레코드 기준 자료형이 두 주차에서 동일했다.
- `page`, `total`, `size`, `offset` 같은 페이지네이션 필드가 없다.
- 연관어 응답 건수는 주차의 실제 연결 관계 수에 따라 달라진다.
- 고정된 TOP 10·20·200 응답은 전체 댓글·키워드 모집단이 아니라 화면 제공용 상위 집계로 해석해야 한다.

### 7.6 요청 메타데이터 보충이 필요한 응답

일부 JSON은 요청한 프로그램과 주차가 응답 레코드에 포함되지 않는다. MariaDB raw 테이블 적재 시 요청 메타데이터에서 식별자를 보충해야 한다.

| 데이터 | 응답의 `pjseq` | 응답의 `nweek` | 적재 시 처리 |
|---|---|---|---|
| 댓글 키워드 | 없음 | 있음 | 요청의 `pjseq` 추가 |
| 긍정댓글 키워드 | 없음 | 있음 | 요청의 `pjseq` 추가 |
| 감성 추이·분포 | 없음 | 있음 | 요청의 `pjseq` 추가 |
| 감성 워드클라우드 | `programid`로 있음 | 있음 | `programid`를 `pjseq`와 대응 |
| 연관어 중심·조합·네트워크 | 없음 | 없음 | 요청의 `pjseq`와 `nweek` 모두 추가 |

요청 식별자를 보충한 값은 RACOI 응답 원문과 구분할 수 있도록 `request_pjseq`, `request_nweek` 또는 수집 실행 메타데이터 컬럼으로 관리한다.

### 7.7 감성 점수 구조 검증

| 요청 주차 | 반환 범위 | 레코드 수 | 긍정+부정 합계 | NULL 점수 |
|---|---|---:|---|---:|
| `202646` | `202646`~`202633` | 14 | 모든 주차 1.0 | 0 |
| `202645` | `202645`~`202632` | 14 | 모든 주차 1.0 | 0 |

감성 추이 API는 요청 주차를 끝점으로 하는 14주 이동 구간을 반환한다. `positivescore`와 `negativescore`는 건수가 아니라 합계 1의 비율이며, 응답만으로 감성 분석 표본 수를 알 수 없다.

### 7.8 워드클라우드 주차 비교

| 주차 | 프로그램 ID | 긍정 코드 1 | 부정 코드 2 | 중립 코드 3 | 합계 |
|---|---:|---:|---:|---:|---:|
| `202646` | 11487 | 25 | 22 | 153 | 200 |
| `202645` | 11487 | 27 | 24 | 149 | 200 |

이 건수는 댓글 감성 건수가 아니라 API가 반환한 워드클라우드 키워드 레코드 수다. 중립 키워드가 153건이라는 사실을 중립 댓글 비율 76.5%로 해석하면 안 된다.

## 8. 댓글반응 분석 가능성 결론

### 8.1 Q4 관심 주제 분석

Q4는 다음 공개 집계를 사용해 구현할 수 있다.

| 활용 데이터 | 사용 가능 내용 | 제약 |
|---|---|---|
| 댓글 키워드 TOP 20 | 프로그램·주차별 주요 관심 키워드와 빈도 | 상위 20개만 제공 |
| 긍정댓글 키워드 TOP 20 | 긍정 맥락에서 자주 등장한 키워드 | 부정 키워드 전용 TOP 20은 없음 |
| 감성 워드클라우드 | 긍정·부정·중립 키워드와 빈도 | 최대 200개, 전체 모집단 여부 불명 |
| 연관어 조합·네트워크 | 키워드 간 동시 등장 관계와 빈도 | 응답에 프로그램·주차 식별자 없음 |

TF-IDF와 주제 점수는 제공된 키워드 집계 범위 안에서 계산한다. 상위 키워드 절단으로 누락된 롱테일 키워드가 있으므로 전체 댓글 단어 분포라고 표현하지 않는다.

### 8.2 Q6 감성 위험 분석

Q6에서 바로 구현 가능한 항목:

- 프로그램·주차별 긍정 비율
- 프로그램·주차별 부정 비율
- 최근 14주 긍정·부정 추이
- 전주 대비 부정 비율 변화
- 부정 코드 워드클라우드의 주요 키워드

현재 응답만으로 구현할 수 없는 항목:

- 긍정·중립·부정 3분포 비율
- 긍정·중립·부정 댓글 건수
- 감성 분석 전체 표본 수
- 댓글 원문을 통한 분류 결과 재검증
- 중립 비율을 포함한 100% 누적 막대그래프

### 8.3 Q6 그래프 명세 판단

| 그래프 | 기존 계획 | 현재 데이터 기준 판단 |
|---|---|---|
| 6-1 감성 분포 | 긍정·중립·부정 100% 누적 막대 | 추가 공식 원천이 없으면 긍정·부정 2분포로 수정 필요 |
| 6-2 부정 감성 추이 | 최근 8주 부정 비율 | 14주 응답 중 최근 8주를 SQL에서 선택하여 구현 가능 |

중립 비율을 0으로 간주하거나 워드클라우드 키워드 건수로 대신 계산하지 않는다. 추가 공식 원천을 찾기 전까지 6-1 그래프의 상태는 `설계 변경 검토`로 기록한다.

### 8.4 위험 판정의 제한

부정 비율과 변화는 계산할 수 있지만 감성 표본 수가 제공되지 않으므로 최소 표본 기준을 직접 적용할 수 없다. 후보별 댓글·키워드 제공 여부와 워드클라우드 레코드 수를 데이터 충분성 보조 정보로 표시하되, 이를 실제 댓글 수로 표현하지 않는다.

## 10. 수집 모듈 구현에 반영할 결정

1. 인터넷반응과 종합반응은 공식 `mexceldown.do` POST 다운로드를 사용한다.
2. Excel은 응답 바이트를 수정하지 않고 XLSX로 보존한다.
3. 파일 형식은 MIME과 ZIP 시그니처를 함께 검사한다.
4. 실제 데이터 범위는 XLSX `dimension`에 의존하지 않고 행 노드와 헤더 위치로 판단한다.
5. 인터넷반응은 2단 헤더, 종합반응은 3단 헤더 구조를 메타데이터에 기록한다.
6. 댓글반응은 공개 JSON POST API를 원천별로 저장한다.
7. JSON 응답은 `Content-Type` 헤더가 없을 수 있으므로 본문 파싱 검증을 수행한다.
8. 댓글반응 최신 주차는 인터넷반응 최신 주차와 별도로 조회한다.
9. 원본 파일은 파일 시스템에 보존하고 이슈 #5에서 행 단위 MariaDB raw 테이블로 적재한다.
10. Q6의 중립 감성 비율은 미제공 상태로 기록하고 그래프 명세 변경 여부를 후속 검토한다.

## 11. 남은 확인 사항
